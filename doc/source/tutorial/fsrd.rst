Fuzzy Spectral Region Decomposition (:func:`scipy.linalg.fsrd`)
===============================================================

.. currentmodule:: scipy.linalg

:func:`fsrd` fits a *data-driven* linear model to a dynamical system.  It
belongs to the family of Koopman / Dynamic Mode Decomposition (DMD) methods:
given a matrix of snapshots of a system taken at successive times, it looks for
a linear operator that advances the state one step in time, and reports that
operator's eigenvalues, modes and amplitudes.

Plain DMD fits a *single* global linear operator, which cannot capture a system
whose behaviour changes across the record (different dynamical regimes, a
chaotic attractor with more than one lobe, a transient followed by a limit
cycle).  Fuzzy Spectral Region Decomposition instead partitions the snapshot
matrix into fuzzy, overlapping regions, fits a local DMD operator in each, and
blends the local reconstructions with smooth membership weights.  How many local
operators to use is chosen automatically from the data, by comparing the
Bayesian information criterion of the whole model as the tree is grown and again
as it is pruned back.

The input layout
----------------

``fsrd`` expects a 2-D array ``a`` of shape ``(M, T)`` where **each column is a
state of the system at a successive time step** and each row is one state
coordinate (a sensor, a spatial location, or a time-delay copy -- see below).
``T`` must be at least 2.

A single linear system
----------------------

If the data really is generated by one linear map, a single region reconstructs
it (almost) exactly and recovers its spectrum.  Here we integrate a plane
rotation by angle ``theta = 0.3`` per step:

    >>> import numpy as np
    >>> from scipy.linalg import fsrd
    >>> theta = 0.3
    >>> A = np.array([[np.cos(theta), -np.sin(theta)],
    ...               [np.sin(theta),  np.cos(theta)]])
    >>> x = np.empty((2, 60))
    >>> x[:, 0] = [1.0, 0.0]
    >>> for k in range(59):
    ...     x[:, k + 1] = A @ x[:, k]

    >>> res = fsrd(x, max_depth=0)
    >>> res.n_regions
    1
    >>> bool(np.allclose(res.reconstruction, x, atol=1e-6))
    True

The continuous-time eigenvalues :math:`\omega = \ln(\lambda)/\Delta t` are
returned per region; their imaginary part is the angular frequency, so we
recover ``theta``:

    >>> round(float(np.abs(res.regions[0].eigenvalues.imag).max()), 3)
    0.3

``max_depth=0`` disables splitting, so this call is ordinary exact DMD.

Nonlinear signals and time-delay embedding
-------------------------------------------

A single scalar signal is turned into a snapshot matrix by *time-delay
embedding*: stack shifted copies of the signal as rows to form a Hankel matrix.
This is the standard way to apply DMD/Koopman methods to a measured time
series.  The signal below switches from a fast to a slow oscillation halfway
through -- a change of regime that a single global operator cannot represent:

    >>> t = np.linspace(0, 60, 1200)
    >>> signal = np.where(t < 30, np.sin(2.0 * t), np.sin(0.5 * t))
    >>> delays = 50
    >>> cols = signal.size - delays
    >>> H = np.array([signal[d:d + cols] for d in range(delays + 1)])
    >>> H.shape
    (51, 1150)

Compare a single global operator against the adaptive decomposition:

    >>> def resid(r):
    ...     return np.linalg.norm(r.reconstruction - H) / np.linalg.norm(H)
    >>> global_dmd = fsrd(H, dt=0.05, max_depth=0)
    >>> multi = fsrd(H, dt=0.05, max_depth=3)
    >>> bool(multi.n_regions > 1)
    True
    >>> bool(resid(multi) < 0.2 * resid(global_dmd))
    True

The global fit leaves a large residual (about 0.79 here) because no single
linear operator matches both halves; the multi-operator model drives it down to
a few percent by devoting separate operators to the two regimes.

Inspecting the local operators
------------------------------

Each entry of ``res.regions`` is an ``FSRDRegion`` describing one local
operator: its continuous-time ``eigenvalues``, DMD ``modes``, ``amplitudes``,
the ``bounding_box`` of the region within the snapshot matrix, its tree
``level`` and fitted ``rank``:

    >>> region = multi.regions[0]
    >>> region.eigenvalues.shape == (region.rank,)
    True
    >>> len(region.bounding_box)
    4
    >>> growth = region.eigenvalues.real       # growth/decay rate
    >>> frequency = region.eigenvalues.imag    # angular frequency
    >>> growth.shape == frequency.shape
    True

Forecasting
-----------

Passing ``forecast=n`` extends the reconstruction ``n`` columns beyond the input
by continuing each region's fitted dynamics.  Because the amplitudes are a
least-squares fit to the observed data, an oscillatory system is continued
faithfully:

    >>> res = fsrd(x, max_depth=0, forecast=20)
    >>> res.reconstruction.shape
    (2, 80)
    >>> future = np.empty((2, 80))
    >>> future[:, 0] = x[:, 0]
    >>> for k in range(79):
    ...     future[:, k + 1] = A @ future[:, k]
    >>> bool(np.allclose(res.reconstruction[:, 60:], future[:, 60:], atol=1e-4))
    True

Choosing parameters
-------------------

- ``max_depth`` bounds how many times the tree may split (``0`` is plain DMD).
  Deeper trees can capture more regimes but cost more; growth also stops on its
  own once a whole level no longer improves the BIC.  Each level doubles the
  regions that are grown before pruning, so raise it with care.
- ``theta`` (:math:`\Theta \ge 1`) is the complexity penalty; larger values
  favour fewer regions.
- ``oblique=False`` restricts splits to axis-aligned (time or coordinate)
  boundaries, which is faster; the default ``True`` also allows diagonal region
  boundaries.
- ``rcond`` and ``eta`` control the per-region SVD truncation and the membership
  cutoff.
- ``prune=True`` (the default) runs the backward pass that performs the model
  selection, merging regions back together while that does not worsen the BIC.
  With ``prune=False`` you get the deliberately over-grown tree the forward pass
  produced, which usually has more regions than the data supports; that setting
  is for inspecting the growth, not for modelling.

See the :func:`fsrd` reference for the full description and the algorithm's
provenance.
